# AgroRadar AI — демонстрация по Wi-Fi для жюри

## Быстрый запуск

На ноутбуке с установленным AgroRadar AI:

1. Подключись к **доверенному Wi-Fi** (или раздай хот-спот с собственного телефона / маршрутизатора). Ноутбук и телефоны жюри должны быть клиентами одной сети **без изоляции устройств**.
2. Закрой обычные окна AgroRadar AI при необходимости. **Дважды нажми DEMO_WIFI.bat** в корне проекта.
3. Скрипт автоматически найдёт IPv4 адреса, соберёт production React, выберет доступный порт и запустит FastAPI+React на одном адресе.
4. При первом запуске, если нет правила брандмауэра, скрипт спросит: `Разрешить ... через UAC? [Y/N]`. Введи **Y** только в доверенной локальной сети и подтверди окно Windows. Правило ограничено профилем **Private**, доступом **LocalSubnet**, портом и Python процесса.
5. На ноутбуке откроется страница **QR-кодов** вида `http://127.0.0.1:18765/wifi/connect`. Если адресов несколько, выбери адрес подключённой Wi-Fi сети (обычно `192.168.*.*`).
6. На ноутбуке открой ссылку **127.0.0.1** для администратора, зайди под прежним логином `admin`, в разделе **«Пользователи»** создай временного **наблюдателя** (например, логин `judge01`, длинный отдельный пароль).
7. Дай жюри отсканировать QR-код. На своих телефонах они открывают `http://<IP-НОУТБУКА>:<ПОРТ>/` и входят под логином наблюдателя. Они смогут смотреть карту и поля, прогнозы, риски, историю и спрашивать DeepSeek, но не редактировать данные.
8. После защиты нажми **Ctrl+C** в окне DEMO_WIFI.bat, чтобы остановить Wi-Fi сервер. Удали/смени временные аккаунты наблюдателей.

**Обычный START_AGRORADAR.bat не изменён**: в обычном режиме проект работает только с текущего ноутбука.

## Почему два разных адреса не нужны

В Wi-Fi-режиме Vite **не запускается в сети**. Сначала собирается `frontend/dist`, затем **один FastAPI-процесс** на динамически выбранном порту отдаёт и frontend, и защищённые эндпоинты `/api/*`.

Таким образом, телефон использует **один и тот же IP/порт** для HTML, карты и запросов. Cookie авторизации относится к тому же адресу, CSRF работает как прежде. Никакого отдельного адреса 127.0.0.1:8000 на телефоне нет.

Порты проверяются привязкой к **0.0.0.0**, а не 127.0.0.1. При отказе Windows скрипт пробует другой порт. При изменении сети/адреса **перезапусти скрипт**, чтобы QR обновились.

## Как подготовить логины

Для мобильной демонстрации используй только **наблюдателей** с отдельными паролями. Доступ администратора в Wi-Fi-режиме намеренно ограничен соединениями с самого ноутбука (127.0.0.1). Попытка входа `admin` с телефона вернёт HTTP 403. Это защищает постоянный пароль администратора от передачи по локальному HTTP.

Пароль `backend/data/admin_access.txt`, ключи в `backend/.env` и хеши пользователей НЕ передаются в браузер и не должны публиковаться в GitHub.

## Интернет и карты

- **Frontend, API, вход, сохранённые поля и объяснимые правила** обслуживаются локально.
- Яндекс Карты, OpenWeather и DeepSeek требуют интернет-доступа (на ноутбуке и/или телефонах).
- Если API Яндекс Карт отклоняет новый IP-origin/HTTP Referer или недоступен, приложение показывает **резервную OpenStreetMap-карту** с полигонами и возможностью выбирать поля. Резервная карта — схема, а не спутниковый слой, и не позволяет редактировать контуры.
- При отсутствии интернета OpenWeather не вернёт актуальный прогноз, но приложение покажет отсутствие данных, а не выдуманную погоду. Демоданные помечены как DEMO.
- Локальный сервер и экран QR никак не шлют адреса сторонним генераторам QR.

## Диагностика за минуту

| Симптом | Проверить |
|---|---|
| Не открывается адрес телефона | Ноутбук и телефон в одной Wi-Fi-сети? Порт в QR совпадает с консолью? Нет Guest/Client Isolation? Windows сеть имеет **Private**? |
| Видно `[WinError 10013]` | Скрипт перебирает резервные порты; если все запрещены — посмотри `netsh interface ipv4 show excludedportrange protocol=tcp` и правила защиты Windows |
| QR на ноутбуке открыт, на телефоне соединение сброшено | Windows Defender Firewall: разрешён ли вход для выбранного порта и **Python из backend/.venv/Scripts/python.exe** в профиле Private, удалённый адрес LocalSubnet? |
| Телефон открывает вход, но пароль не подходит | Используй **логин наблюдателя**, созданного администратором, а не `admin`. Учитывай регистр пароля. |
| Запрет 403 на изменение поля | Ожидаемое поведение: наблюдатель не может изменять данные. |
| Карта не отображается на IP-адресе | Проверь ключ/HTTP Referer Яндекс API; используй запасную схему OpenStreetMap. Для тайлов также нужен интернет. |
| Открыл старый интерфейс после Pull | Перезапусти DEMO_WIFI.bat — он заново выполняет `npm run build`. На телефоне обнови вкладку. |
| QR показывает неверный IP после смены Wi-Fi | Закрой и запусти DEMO_WIFI.bat повторно; скрипт повторно определит IPv4 и порт. |
| На корпоративном Wi-Fi не видно другие устройства | Вероятно включена клиентская изоляция (Guest isolation). Варианты: отдельный маршрутизатор или доверенный телефонный хот-спот. |

### Если несколько адаптеров или нужен фиксированный IP/порт

Можно запустить с явно выбранным IPv4:

```bat
DEMO_WIFI.bat --ip 192.168.1.105
```

Для фиксированного порта:

```bat
DEMO_WIFI.bat --ip 192.168.1.105 --port 18765
```

Адрес должен реально принадлежать сетевому адаптеру ноутбука, а порт не должен быть занят/зарезервирован. При автоматическом режиме выводятся все подходящие адреса Wi-Fi/Ethernet и отдельные QR-коды.

### Удаление firewall-правила после мероприятия

Правило ограничено **Private + LocalSubnet + точный Python + выбранный TCP-порт**, но может сохраниться после закрытия приложения. Если больше не нужно, открой PowerShell **от имени администратора** и выполни:

```powershell
Get-NetFirewallRule -DisplayName 'AgroRadar AI WiFi Demo (Private LAN only)' -ErrorAction SilentlyContinue | Remove-NetFirewallRule
```

## Ограничения безопасности

**HTTP внутри Wi-Fi не шифрует передаваемые данные.** Используй только доверенный Wi-Fi/хот-спот с WPA2/WPA3, демонстрационные (не конфиденциальные) поля и временные логины наблюдателей. Не демонстрируй реальные секретные данные агропредприятия в публичной сети. Не используй это как промышленный публичный сервер.

Windows Firewall, политики организации, изоляция Wi-Fi или операторская блокировка могут физически запретить связь: нельзя гарантировать доступ во всех сетях без теста на конкретном месте.

## Контрольная проверка перед выступлением

- На ноутбуке открыть `127.0.0.1:<порт>/wifi/connect`, увидеть адрес и QR.
- На **двух телефонах** с тем же Wi-Fi открыть QR, проверить вход наблюдателей.
- На телефоне открыть обзор, карту, переключить поля, увидеть погодные риски.
- Попробовать ИИ-чат (нужен работающий DeepSeek и интернет).
- Проверить, что с телефона нельзя войти под `admin` и нельзя удалить поле.
- Отключить интернет на телефоне (не Wi-Fi): при доступном интернете у ноутбука локальная страница и API продолжат открываться; тайлы/внешние JS карты могут зависеть от интернета самого телефона.

Работающий на Windows ноутбук — сервер. Если закрыть его, все телефоны потеряют доступ.
