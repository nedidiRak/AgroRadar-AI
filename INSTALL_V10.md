# AgroRadar AI v1.0 — управление полями (патч к v0.9)

## Что исправлено

Раньше «Обвести» вызывало `PUT /api/fields/{id}/geometry`, поэтому изменяло **существующее** поле, выбранное в правой карточке. Создания нового ID не происходило. Кроме того, backend содержал строго 4 записи `FIELDS`, а демонстрационная погода индексировалась только по ID 1–4.

Теперь:
- **Новое поле** → нарисовать минимум 3 угла → **Далее: название и культура** → заполнить обязательные название/культуру и необязательное описание → **Создать поле**. `POST /api/fields` сохраняет **новый ID**, геометрию, площадь и центр.
- **Изменить контур** → корректировка геометрии выбранного существующего поля.
- Кнопки **Изменить / Удалить** расположены справа в карточке выбранного поля.
- Можно создать 5-е, 6-е и последующие поля. Все отображаются в списке, на карте, в GeoJSON, в погоде и в суммарных показателях.
- Исторические границы `backend/data/field_geometries.json` продолжают считываться. Создание/удаление/редактирование сохраняются в **новом** `backend/data/fields.json`.
- Для пользовательских полей «Сбросить контур» недоступен — без геометрии пользовательское поле не имеет границы. Используйте «Изменить контур».

## Установка под Windows 10

1. В GitHub Desktop сделайте коммит `Backup AgroRadar v0.9 before Field Manager`.
2. Остановите серверы (в обоих окнах PowerShell `Ctrl+C`).
3. **Сохраните резервную копию** каталога `C:\Users\domar\AgroRadar-AI\backend\data`, если уже рисовали поля. Архив не содержит `backend/data` и не удаляет эти файлы.
4. Распакуйте этот ZIP. Скопируйте папки `backend`, `frontend` и файл `.gitignore` из архива в `C:\Users\domar\AgroRadar-AI`, согласившись на замену файлов. **Не удаляйте другие файлы репозитория.**
5. Убедитесь, что `backend/.env` и `frontend/.env.local` на месте. Патч их не содержит и не заменяет.
6. Запустите `START_AGRORADAR.bat` в корне проекта или два терминала вручную:

```powershell
cd "C:\Users\domar\AgroRadar-AI\backend"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

```powershell
cd "C:\Users\domar\AgroRadar-AI\frontend"
npm.cmd run dev
```

7. Откройте `http://localhost:5173` (именно **localhost** для Яндекс API), затем обновите страницу `Ctrl+F5`.

## Самопроверка

1. Убедитесь, что список содержит исходные четыре поля (и что сохранённые ранее контуры не пропали).
2. Выберите **Новое поле**. Переместите карту на другой участок, отметьте 4 угла.
3. Нажмите **Далее: название и культура**. Название: `Поле Тестовое`, культура: `Ячмень`, описание: `Тест созданного участка`.
4. Нажмите **Создать поле**. Теперь счётчик должен показать **5**, а выбранным должно стать «Поле Тестовое» со своими координатами и границей.
5. Нажмите **Изменить**, переименуйте и смените культуру.
6. Нажмите **Удалить**, подтвердите. Должно снова остаться **4** поля.
7. Перезапустите FastAPI и обновите страницу. Данные должны сохраняться.

## API

- `POST /api/fields` — создать по координатам GeoJSON `[lon, lat]` и метаданным
- `PUT /api/fields/{id}` — изменить название, культуру, описание
- `DELETE /api/fields/{id}` — удалить поле
- `PUT /api/fields/{id}/geometry` — изменить границы
- `DELETE /api/fields/{id}/geometry` — вернуть исходные демонстрационные границы (только для исходных демополей)
- `GET /api/dashboard`, `GET /api/fields`, `GET /api/fields.geojson` — возвращают актуальный список
- `GET /docs` — Swagger.

Данные хранятся локально в JSON для MVP; для многопользовательской промышленной версии нужна БД, аутентификация и резервное копирование.

**Секреты** не включены в архив. Убедитесь, что в `.gitignore` присутствуют `backend/data/fields.json`, `backend/data/field_geometries.json`, `backend/.env`, `frontend/.env.local` — реальные данные участков и ключи нельзя коммитить бездумно.
