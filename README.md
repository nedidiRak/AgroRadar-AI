# AgroRadar AI v0.4 — геоданные + OpenWeather

## Что реализовано

- Карта **Leaflet с настоящими координатами WGS84**, GeoJSON полигонами и выбором поля. Никакие сторонние карты или тайлы не загружаются, нет API-ключа карты.
- Контуры полей в этой версии **сгенерированы для демонстрации** из площади и центра. Это НЕ геодезические/кадастровые границы. API `GET /api/fields.geojson` готов для последующей замены на реальные GeoJSON участков.
- OpenWeather **Current Weather + 5 day / 3 hour Forecast**; ключ остаётся только на backend. API кэшируется на 15 минут в памяти процесса.
- Предварительный риск заморозка по **минимальной температуре следующих 24 часов**. Это индикатор, а не обученная ML-модель или прогноз потерь урожая.
- Если ключ OpenWeather не задан, UI явно сообщает о **ДЕМО**. Ошибка ключа возвращает `503`, не маскируется под реальные данные.

## Установка

**Windows PowerShell, backend**:

```powershell
cd C:\Users\domar\AgroRadar-AI\backend
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

В файле `backend/.env` задайте `OPENWEATHER_API_KEY=ваш_ключ` или оставьте пустым для демо. Ключ OpenWeather НЕ нужно помещать в `frontend/.env.local`. Файл `.env` исключён из Git. После изменения ключа перезапустите backend.

**Windows PowerShell, frontend (другое окно)**:

```powershell
cd C:\Users\domar\AgroRadar-AI\frontend
npm.cmd install
npm.cmd run dev
```

Откройте http://localhost:5173, API-документация: http://127.0.0.1:8000/docs.

## API

- `GET /api/health`
- `GET /api/fields` — центры полей
- `GET /api/fields.geojson` — полигоны, в `properties.geometry_source=demo_generated`
- `GET /api/fields/{id}/weather` — наблюдение
- `GET /api/fields/{id}/forecast` — минимальная прогнозная температура за 24 ч
- `GET /api/fields/{id}/risks` — объяснимый индикатор
- `GET /api/dashboard` — все поля, погода, прогноз и риски

## Что нужно перед реальными испытаниями

1. Заменить фиктивные поля и сгенерированные полигоны на действительные границы GeoJSON из разрешённого источника.
2. Проверить применимость температурных порогов под культуры, фазы и период года. Прогноз с шагом 3 ч не гарантирует обнаружения краткосрочного заморозка между интервалами.
3. Для сотен полей — база PostGIS, серверный кластер/упрощение геометрий, группировка погодных запросов по ячейкам, Redis-кэш и фоновое обновление (текущий in-memory кэш рассчитан на MVP).
4. При необходимости географической подложки — **лицензионно разрешённые** локальные MBTiles/PMTiles или отдельный настраиваемый провайдер. Не скачивайте тайлы OSM/Яндекса для офлайна без соответствующих разрешений. Если используются данные OSM, их атрибуция обязательна.
5. После обновления не удаляйте `README.md` и `.gitignore`. Старый `frontend/.env.local` с Яндекс-ключом больше не используется. Рекомендуется удалить его локально и отозвать неиспользуемый ключ.
