# AgroRadar AI — Final Suite 3.5

**Gorin's team · IT-спринт · кейс Русагро «Агро-Радар»**

AgroRadar AI — локальная веб-платформа для демонстрации анализа погодных рисков сельскохозяйственных полей: Яндекс Карты, OpenWeather, объяснимые правила, ИИ-агроном DeepSeek, история прогнозов, центр предупреждений, журнал изменений, отчёты и резервное копирование.

Это **работающий конкурсный прототип**, но не проверенная модель потерь урожая или промышленная система управления сельхозпредприятием.

## Что входит в единую версию 3.5

| Блок | Что доступно |
|---|---|
| Карта | Спутниковая/гибридная Яндекс Карта, создание и редактирование полигонов, импорт/экспорт GeoJSON |
| Погода | OpenWeather текущая погода и 3-часовой модельный прогноз до 24 ч, кеш, деградация отдельных участков |
| AgroRisk Engine 3.0 | Четыре проверяемых погодных правила, источник, полнота данных, паспорт поля и действия агронома |
| ИИ-агроном | DeepSeek с текущим контекстом, историей риска, внутренними справочными заметками, экспортом диалога |
| Пользователи | Администратор и наблюдатели (просмотр и чат без изменения полей), серверное разграничение прав |
| Центр решений | SQLite история по полям, график, предупреждения OpenWeather и подтверждение обработки |
| Отчёты | Печатный A4 HTML («Печать → сохранить в PDF»), CSV поля и сводная таблица по хозяйству |
| Безопасность | HttpOnly сессии, CSRF, ограничение попыток входа, журнал действий, секреты вне Git |
| Резервные копии | Перед изменениями JSON создаются копии с ротацией; администратор скачивает ZIP **без паролей и API-ключей** |
| Качество | GitHub Actions: pytest и сборка React/TypeScript, offline-регрессионные тесты |

## Запуск на Windows (сохранение существующих настроек)

1. В GitHub Desktop нажать **Fetch origin**, затем **Pull origin**, чтобы получить итоговый релиз после объединения PR.
2. Не удалять и не заменять файлы `backend/.env`, `frontend/.env.local`, `backend/data/fields.json`, `backend/data/field_geometries.json`, `backend/data/admin_access.txt`, `backend/data/viewer_accounts.json`.
3. При уже установленном проекте запустить **START_AGRORADAR.bat** как раньше.
4. Открыть `http://localhost:5173`.
5. Войти как `admin` с прежним локальным паролем; наблюдатели входят по своим логинам и паролям.
6. Открыть **Центр решений**. При каждом обновлении страницы «Обзор» создаётся сохранённый срез текущего прогноза (если изменились показатели или прошли 30 минут).

Не публикуйте в чат или GitHub содержимое секретных файлов.

### Первая установка, если папки окружения отсутствуют

Python 3.12+ и Node.js необходимы. В PowerShell:

```powershell

.\.venv\Scripts\python.exe -m pip install -r requirements.txt
cd ..\frontend
```

Ключи в **backend/.env**: OPENWEATHER_API_KEY и DEEPSEEK_API_KEY, модель DEEPSEEK_MODEL (необязательно). Ключ Яндекс Карт: **frontend/.env.local** с VITE_YANDEX_MAPS_API_KEY. Если OpenWeather не настроен, данные помечены **demo**. Без DeepSeek можно использовать карту, правила, центр решений и отчётность.

## Роли

- **Администратор:** поля, границы, журнал наблюдений, добавление/удаление наблюдателей, принятие предупреждений, резервное копирование, журнал действий.
- **Наблюдатель:** просмотр реестра, карты, прогноза, анализа рисков, истории, предупреждений, отчётов, диалог с DeepSeek. Изменение данных запрещено не только кнопками, но и FastAPI.
- Публичный интернет без дополнительного укрепления безопасности **не поддерживается**. Cookie сессии по умолчанию работают только на локальном HTTP; при HTTPS-развёртывании потребуются HTTPS и AGRORADAR_SECURE_COOKIES=1, а также отдельная проверка защиты и хранилища.

## Данные, история и сохранность

- Исходные пользовательские поля: `backend/data/fields.json`.
- Ранее сохранённые контуры: `backend/data/field_geometries.json`.
- Пароль администратора и хеши наблюдателей остаются в собственных файлах.
- **Новые** данные: `backend/data/monitoring.sqlite3`, автоматически создаётся SQLite при обращении к истории или первом обновлении сводки. Старые файлы **не мигрируются и не перезаписываются**.
- Перед заменой существующего каталога, геометрий и списка пользователей сохраняется предыдущая версия в `backend/data/backups/`, по 15 копий каждого файла.
- Нажмите «Центр решений → Резервная копия данных», чтобы скачать приватный ZIP с полями, контурами и историей. **Пароли и ключи исключены намеренно**. Для полного переноса логинов их придётся переносить отдельно по защищённому каналу.
- Чтобы восстановить ZIP: закрыть сервер, отдельно сохранить текущее `backend/data`, затем скопировать файлы из папки `data/` архива в `backend/data` и запустить приложение.
- История фиксируется при обращении к сводке, **не каждые три часа автоматически**, пока приложение закрыто. Хранится максимум 240 снимков на поле; одинаковые данные не записываются чаще получаса.

## Проверка релиза

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest -q
cd ..\frontend
npm.cmd run build
```

Без настоящих внешних API ключей тесты используют мок-ответы. В GitHub Actions те же тесты выполняются на каждый PR и push в main.

### Сценарий демонстрации для жюри на 5 минут

1. **0:00–0:40** — боль: погодные источники, наблюдения и действия агронома в разных местах; открыть сводку.
2. **0:40–1:20** — карта: Яндекс снимок, контур одного поля, площадь, паспорт.
3. **1:20–2:20** — AgroRisk 3.0: раскрыть правила четырёх факторов и качество источника; переключить *Сценарий: заморозок*, пояснить «симуляция, не реальная погода».
4. **2:20–3:10** — открыть «Центр решений»: история, график, предупреждения; при отсутствии LIVE честно объяснить, почему демо-риски не создают реальные оповещения.
5. **3:10–4:00** — отчёт: сформировать печатную страницу, показать сохранение PDF; показать CSV и локальную резервную копию.
6. **4:00–4:40** — ИИ: спросить DeepSeek о выбранном поле, раскрыть внутренние заметки и источник данных.
7. **4:40–5:00** — наблюдатель vs администратор; защита прав, масштабирование и честные ограничения.

**Рекомендуется записать резервную демоверсию показа заранее:** живые Яндекс Карты, OpenWeather и DeepSeek зависят от интернета, ключей и доступности внешних сервисов. Работа сценариев и офлайн-тестов не доказывает работу этих сервисов на конкретной площадке.

## Архитектура и ограничения

```
React + TypeScript + Vite + Яндекс Карты 2.1
        | HTTP /api/* через Vite proxy
FastAPI (локальный выбранный порт, 127.0.0.1)
        |-- auth (admin/viewer, session + CSRF)
        |-- поля (JSON, обратная совместимость)
        |-- OpenWeather (ограничение одновременных запросов + кеш 15 мин)
        |-- AgroRisk Engine 3.0 (детерминированные правила)
        |-- DeepSeek (серверный контекст + внутренние заметки)
        |-- SQLite monitoring.sqlite3 (история, предупреждения, журнал)
        |-- отчёты (A4 HTML + CSV) / безопасные ZIP-резервные копии
```

**Ограничения:** SQLite здесь хранит историю и тревоги, но каталог полей и пользователей пока в JSON с блокировкой одного процесса. Это подходит для локального конкурсного показа, но не гарантирует безопасную многопроцессную работу. 500 полей проверяются в тесте истории без реальных API; время получения **500 живых прогнозов** зависит от ограничений OpenWeather, сети и числа вызовов (по два на поле) — утверждать, что это уже промышленная скорость, нельзя. Для внедрения нужны PostgreSQL, очередь фонового обновления, единая ролевая модель, TLS, аудит, резервирование и калибровка моделей на данных хозяйств.

### Бизнес-эффект

В исходном кейсе Русагро указаны **целевые** 10–15% снижения потерь урожая и 7–10% экономии ресурсов. Эти проценты — **ожидания заказчика**, не измеренный результат нашей реализации. Для доказательства экономического эффекта нужна пилотная эксплуатация и методика сравнения.

Наша проверяемая ценность сейчас: один интерфейс, прозрачные правила, история принятия решений и последовательность действий без сокрытия отсутствующих данных.
