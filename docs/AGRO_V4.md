# AgroRadar AI 4.0 — финальный инженерный релиз

Русагро · Школа 21 · IT-спринт · 20 ноября 2026.

## Что меняется

- Проверяемое объяснение сухой жары: выводится температура и влажность именно того 3-часового интервала, который вызвал предупреждение.
- Агрономический скрининг для пшеницы: погодные предпосылки бурой ржавчины с первоисточниками UGA Extension и USDA ARS; **не диагноз заболевания**.
- Семидневная оценка P − ET₀ (осадки минус эталонная испаряемость), по данным Open-Meteo. Источник вызывается только для выбранного поля. Это **не влажность почвы, не доказанная засуха и не норма полива**.
- Действия по полю: создать задание, указать ответственного/срок, взять в работу, закрыть с обязательным результатом. Все изменения проходят серверную проверку прав и сохраняются в SQLite.
- DeepSeek: проверка ключа через официальный GET /models, без генерации платного текста. Статус «Доступен» означает, что провайдер принял ключ при проверке моделей, но не гарантирует баланс для отправки сообщения.
- Ограниченное обновление OpenWeather пакетами в фоне, только при запущенном FastAPI, по явной настройке оператора.
- Реальный тест **создания 500 полей через POST /api/fields** с чтением каталога, GeoJSON и повторной проверкой сохранённых данных.

## Научные обоснования

### Пшеница и бурая ржавчина

[UGA Extension — Identification and Control of Leaf Rust of Wheat](https://extension.uga.edu/publications/detail.html?number=C1060)

[USDA Agricultural Research Service — Wheat Leaf Rust](https://www.ars.usda.gov/midwest-area/stpaul/cereal-disease-lab/docs/cereal-rusts/wheat-leaf-rust/)

Публикации описывают благоприятные условия в районе 15–25 °C и при наличии свободной влаги. Для прототипа применяется **эвристика**, а не научно валидированная модель: два соседних 3-часовых прогнозных интервала с 15–25 °C, влажностью воздуха от 90% и осадками. Влажность воздуха и дождь **не равны** измеренной влаге на листьях. Нужны полевое обследование, данные об инокулюме и восприимчивости культуры. Правило не даёт процента заражения и не назначает обработки. Для других культур оно явно не применяется.

### Баланс P − ET₀

[FAO-56 — Crop evapotranspiration](https://www.fao.org/4/x0490e/x0490e00.htm)

[Open-Meteo — daily precipitation_sum and et0_fao_evapotranspiration](https://open-meteo.com/en/docs)

Отображается только при наличии всех семи **последовательных завершённых UTC-дней**: сумма осадков P, сумма ET₀ и P − ET₀ в мм. Отрицательное значение — превышение эталонного испарительного спроса над осадками, **не** измерение влаги в корнеобитаемом слое и **не** рекомендация по поливу.

Open-Meteo предоставляет бесплатный публичный API для некоммерческого применения; **для промышленного коммерческого внедрения в Русагро необходимо отдельное лицензирование**. Интеграция OpenWeather остаётся основным обязательным источником текущей погоды и прогноза.

## Дополнительные настройки backend/.env

- AGRORADAR_WATER_CONTEXT=1 — позволяет получать семидневную историю по выбранному полю (по умолчанию включено, отключение =0). Кеш 6 часов. При недоступности Open-Meteo блок честно сообщает об отсутствии данных.
- AGRORADAR_AUTO_MONITOR=0 — фоновый мониторинг выключен по умолчанию, чтобы не расходовать лимиты OpenWeather без согласия. Для включения =1.
- AGRORADAR_MONITOR_BATCH=20 — за один проход до 20 полей; верхний лимит 50.
- AGRORADAR_MONITOR_INTERVAL_SECONDS=90 — между пакетами не менее 60 секунд.

Автопроверка работает **только пока запущен сервер**. При 500 полях обход занимает много циклов, и скорость зависит от лимитов и задержек OpenWeather. Утверждать поддержку 500 одновременно обновляемых прогнозов без реального нагрузочного испытания внешних API нельзя.

## Полевые задания

Образец демонстрации: «Центр решений» → погодное предупреждение → «Создать задание» → «Принять в работу» → вписать фактический результат → «Завершить». Задания автоматически не меняют метеорологический риск. Наблюдатели могут читать, но не изменять задания.

API:
- GET /api/fields/{id}/agronomy — только выбранный участок.
- GET /api/ai/check — фактическая проверка доступности DeepSeek.
- GET/POST /api/operations/tasks — просмотр/создание заданий.
- PUT /api/operations/tasks/{id} — изменение статуса с обязательным результатом при закрытии.
- GET /api/operations/monitor — статус фоновой проверки.
- POST /api/operations/monitor/refresh — один ограниченный ручной запуск.

Изменения доступны администратору с CSRF; чтение и ИИ доступны наблюдателям. Старые данные полей, геометрий, логинов и ключей не мигрируются.

## Проверка фактического создания 500 полей

Проверено GitHub Actions 11 ноября 2026 года: в двух успешных прогонах создание 500 полей заняло 11,890 и 7,123 с; чтение всего каталога и GeoJSON — 0,084 и 0,043 с соответственно. Это измерения CI-раннеров, не обещание такого же времени на ноутбуке или в промышленной сети.

CI job **Real API load test (500 created fields)** выполняет в отдельном временном каталоге:
1. 500 последовательных POST /api/fields с валидными и уникальными контурами.
2. Проверку каждого HTTP 201, ID, площади и геометрии.
3. GET /api/fields — 504 записи (4 демонстрационных и 500 новых).
4. GET /api/fields.geojson — 504 контура, из них 500 пользовательских.
5. Повторное чтение с диска, проверку ротации резервных копий.
6. Ещё 20 параллельных созданий для проверки отсутствия потери записей.
7. В консоли вывода CI публикуется **AGRO_500_PROOF** с измеренным временем.

Тест не отправляет запросы настоящему OpenWeather. Не содержит личные данные или локальные секреты.

## Сценарий защиты

1. На ноутбуке показать карту, реальные/демо-источники погоды, паспорт поля, базовые правила.
2. Открыть АгроRisk и объяснить конкретный сработавший метеорологический фактор.
3. Раскрыть «Агрономическая аналитика 4.0», показать UGA/USDA, P−ET₀ и честные ограничения.
4. В «Центре решений» создать и закрыть обследование с текстом результата.
5. Сгенерировать отчёт/CSV, показать историю прогноза и источник.
6. На телефоне жюри показать вход наблюдателя по QR и тот же центр решений без права редактирования.
7. Спросить DeepSeek об этом поле; в случае проблем с интернетом иметь заранее записанный резервный сценарий.

## Честные ограничения

- Это конкурсный прототип, не диагностическая модель заболеваний и не медицинская/агрономическая инструкция по обработке.
- Нет измеренных результатов 10–15% предотвращения потерь урожая или 7–10% экономии ресурсов: это целевые ориентиры из кейса.
- Предыдущий документ docs/AUDIT_2026-11-02.md исторический и содержит уже исправленные недостатки раннего MVP.
- Не проверена промышленная многопроцессная отказоустойчивость на PostgreSQL, SLA внешних API, лицензии коммерческого использования и реакция на полевые данные предприятия.
