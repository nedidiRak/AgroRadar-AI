# AgroRadar AI 4.0 — готовый архив для эксперта

**Эксперту не нужны Python, Node.js, npm, Git и виртуальное окружение.**
Отправь один ZIP: AgroRadar-Expert-Windows-v4.zip (или AgroRadar-Expert-SEND.zip с ключами).

## Как автору получить архив

1. Открой [GitHub Actions](https://github.com/nedidiRak/AgroRadar-AI/actions/workflows/ci.yml).
2. Выбери последний успешный запуск основной ветки main.
3. В разделе Artifacts скачай AgroRadar-Expert-Windows-v4.
4. Распакуй и убедись, что есть AgroRadar-Expert.exe и папка _internal.
5. Для реальных DeepSeek, OpenWeather и Яндекс Карт открой ADD_MY_KEYS.cmd, введи ключи. Скрипт создаст готовый ZIP AgroRadar-Expert-SEND.zip рядом с папкой. **Ключи в нём находятся открытым текстом** и предназначены исключительно для адресной передачи эксперту.
6. Если ключи не нужны, отправляй первый скачанный архив без дополнительных действий.

GitHub-артефакт закрытого репозитория может видеть только владелец, поэтому эксперт получает именно скопированный ZIP.

## Как эксперт проверяет приложение

1. На Windows 10/11 x64 распаковывает архив целиком, не запускает EXE прямо из ZIP.
2. Дважды нажимает AgroRadar-Expert.exe.
3. Приложение открывает страницу в браузере. Адрес отображается в окне программы.
4. Входит как **admin**, пароль **AgroRadar-Expert!2026** (специальный известный пароль только для локальной демонстрации).
5. Проверяет создание, редактирование, сохранение и удаление поля; контуры, отчёты, задания, историю, ИИ и погодные риски.
6. Закрывает окно программы — сервер останавливается; изменения остаются в папке data рядом с EXE.

Эксперт получает полный административный доступ к локальной демонстрационной базе, НЕ роль наблюдателя. Порт открыт только по 127.0.0.1, не в интернет и не в локальную сеть.

## Интернет и ключи

| Модуль | Без ключа | С тестовым ключом |
|---|---|---|
| Реестр, контуры, создание/изменение/удаление | Да | Да |
| История, центр решений, задания, отчёт | Да | Да |
| AgroRisk | Маркированные погодные DEMO данные | Живая погода OpenWeather |
| Карта | OpenStreetMap через интернет | Яндекс Карты при разрешённом Referer |
| ИИ | Только чётко помеченный ДЕМО-сценарий, НЕ DeepSeek | Настоящий DeepSeek |
| Водный контекст | Open-Meteo при доступном интернете | То же |

Можно вручную скопировать settings.env.example рядом с EXE, назвать settings.env и заполнить только:
- OPENWEATHER_API_KEY
- DEEPSEEK_API_KEY
- VITE_YANDEX_MAPS_API_KEY

Эти ключи нельзя добавлять в исходный GitHub-репозиторий. Поставщик Яндекс Карт может требовать разрешить адрес 127.0.0.1 в HTTP Referer.

## Ограничения и безопасность

- Это локальная экспертная копия только для Windows x64, не промышленный сервер.
- Программа без цифровой подписи; SmartScreen или ИТ-политика компании могут запретить запуск. Не отключайте корпоративную защиту, используйте согласованный способ проверки.
- Не содержит никаких пользовательских полей, паролей и приватных API-ключей автора.
- Данные хранятся локально. Для нового чистого испытания после закрытия программы можно удалить папку data только внутри экспертной копии.
- Известный пароль допустим исключительно для приложения на 127.0.0.1. Не используйте эту сборку в открытой сети.
- Для отправленного ZIP с ключами получатель технически имеет к ним доступ.

## Что проверяет GitHub Actions

На Windows запускается npm ci, npm run build, сборка PyInstaller onedir. Затем действительно запускается собранный EXE в изолированной папке и тестируется HTTP: SPA, логин админа, создание поля, изменение, удаление, задания, демо-чат и хранение на диске. Артефакт Windows появляется только после успешного теста.

Обычный START_AGRORADAR.bat и DEMO_WIFI.bat продолжают работать как прежде.
